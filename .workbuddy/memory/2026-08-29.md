## 🎨 背景按钮撞位修复（commit 28f403b）
- **现象**：笔记页 / 算法讲义页滚动过 400px 后，「回到开头」按钮出现在右下角，与 🎨 完全重叠。页面按钮 z-index 2300 > 🎨 200 → **🎨 被整个盖住点不到**。
- **根因（三层叠加）**：旧避让逻辑是写死的
  ```js
  if (document.querySelector('.ol-nav-fab')) bgFab.classList.add('bg-fab-shift');
  @media (max-width:900px) { .bg-fab.bg-fab-shift { bottom: 78px; } }
  ```
  1. 笔记页改版后右下角按钮换成 `.notes-top-btn`，名单里**根本没有它**；
  2. `.bg-fab-shift` 只在 `≤900px` 生效，桌面端加了类**没有任何 CSS 作用**；
  3. `.ol-nav-fab` 桌面是 `display:none`，但 `querySelector` **不看可见性**，白加类。
- **改为实测避让**（`pwa/js/background.js`）：
  - `fabColliders()` 取 🎨 **默认停靠位**（按 CSS `right:20/bottom:20` + `offsetWidth/Height` 反推），与右下角 `FAB_ZONE=240px` 区域内所有**可见** fixed 候选按钮做矩形相交测试；有碰撞 → 抬到最靠上那个之上留 `FAB_GAP=12px`；无碰撞 → `fab.style.bottom=''` 回默认位。
  - **关键坑**：参考矩形**不能读 fab 当前的 bottom**——抬过一次再测就会拿"已抬高"的位置判断，误判为无碰撞，下次又落回原位抖动。必须按 CSS 常量反推。
  - 滚动 / resize 时 rAF 节流重测（页面按钮多随滚动才显示，只在注入时测一次不够）。
  - `FAB_SEL` 选择器名单：`.notes-top-btn, .ol-nav-fab, .dati-nav-fab, [class*="nav-fab"], [class*="top-btn"], [id$="TopBtn"]`。**新增右下角按钮要补这里**。
  - 面板 `placePanel()` 跟随 🎨 实际位置：`bottom = fab.bottom + 48 + 12`。
- **删掉了失效的 `.bg-fab-shift` 规则与类名逻辑**；`.bg-fab` 的 transition 加入 `bottom`，抬升有动画。
- **回归测试** `_test_bg_fab_shift.js`（13 场景全过）：jsdom 真实执行 background.js，用 `data-box="w,h,right,bottom"` 属性模拟布局结果，断言 `bgFab.style.bottom`。
  **jsdom 坑（三个，都踩过）**：
  1. `readyState` 是 `'loading'`（构造后不会自动 complete）→ 必须等 `DOMContentLoaded`，`init()` 才会跑；
  2. **`innerWidth` 默认 1024 / `innerHeight` 默认 768**，不是你在 `beforeParse` 里传入的视口 → 几何比较基准全错，所有碰撞用例静默失败（症状：该触发的都 `got=""`，看着像"逻辑没生效"，其实基准不一致）。必须在 `beforeParse` 里 `Object.defineProperty(w,'innerWidth',{get(){return vw}})`；
  3. jsdom 不一定按 innerWidth 求值 `@media` → 别靠媒体查询造场景，用 `cssExtra` 直接覆盖样式。
  jsdom 未装时优雅跳过（`require` try/catch + `process.exit(0)`），不阻塞其它工作。

## 范围澄清与计数口径修正（commit 62eb514）
- **用户澄清范围**：清理对象 = **已收藏的题 ∩ 错题本里的题**（即「收藏模式下的错题」），其他题的错题一条不碰。范围实现本来就对，用户那句"不是收藏里所有的错题都清理"指的是"别把整个错题本清了"。
- **真正要修的是计数口径**：原计数带 `include_resolved=true`，把「连对 2 次、早已移出错题本的历史记录」也算进去 → 按钮写 5、错题本里只看得见 3 个，数字对不上用户认知。改为不加该参数，与错题本页完全一致。
- **计数口径 ≠ 删除口径**（刻意区分，别"顺手统一"）：
  - 计数：只数未解决（用户看得见的）
  - 真删：按该题的全部错题记录删，含已解决
  - 原因：这些收藏题要彻底移出错题本；若只删未解决、留着已解决行，会因 **30 天复盘机制**又回到复习队列，达不到"移出去"的效果。
- **文案**：把"只动收藏模式下的错题、其他题不受影响"写进按钮 title、禁用态提示、确认框三处。
- **教训**：破坏性按钮的**计数来源**必须等于用户能看见的那个列表（错题本页的默认视图），否则用户会觉得按钮在撒谎。写代码时"顺手把已解决的一起算进去"是最常见的偏差来源。
- APP_VER→`quiz408-app-227a51db68`；删除范围未变，`_test_fav_wrong_reset.js` 29 项仍全过；已 push，远程 HEAD 一致。
