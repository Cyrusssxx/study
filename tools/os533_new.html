大题考点2010-45

五、磁盘调度算法总览与FCFS、SSTF算法（必考手算）

磁盘调度要解决的核心问题是：当多个请求同时到达时，按什么顺序服务。由于寻道时间在存取时间中占主导，调度算法的目标就是尽量减少磁头移动的总距离（平均寻道长度）。

本小节统一用教材主例演示手算：磁盘请求队列为 55, 58, 39, 18, 90, 160, 150, 38, 184，磁头初始位于磁道100（磁道范围0~200），平均寻道长度 = 总移动距离/请求个数9。手算套路是先把请求在数轴上排序，再按算法的"移动规则"逐步累加相邻两步的差值，切忌跳步。排序后请求位置为 18, 38, 39, 55, 58, 90, |100（磁头）, 150, 160, 184 —— 磁头100把请求分成"左边一组（18~90）"与"右边一组（150~184）"，各算法的差异本质上就是两组请求被服务的先后次序以及往返策略的不同：FCFS按到达时间打乱次序、SSTF按距离远近交替取、SCAN按方向一鼓作气扫到端、C-SCAN扫完右侧后跳回左侧起点。

（1）先来先服务（FCFS）：按进程请求访问磁盘的先后顺序调度，是最简单、最公平的算法，无需维护复杂数据结构。优点：公平、简单，请求少且访问扇区物理位置聚集时性能尚可；缺点：当大量进程竞争磁盘时，磁头频繁长距离来回移动，平均寻道距离很大，效率低下，仅适用于磁盘I/O较少的场合。

经典例题②之FCFS：按队列到达顺序依次服务 100→55→58→39→18→90→160→150→38→184。逐步累加相邻距离：|100-55|=45，|55-58|=3，|58-39|=19，|39-18|=21，|18-90|=72，|90-160|=70，|160-150|=10，|150-38|=112，|38-184|=146。总移动距离 = 45+3+19+21+72+70+10+112+146 = 498个磁道，平均寻道长度 = 498/9 ≈ 55.3。

图5.22 FCFS——按到达顺序服务，轨迹最乱

（2）最短寻道时间优先（SSTF）：每次选择距离当前磁头位置最近的请求进行调度，使单次寻道时间最短。该策略不能保证平均寻道时间全局最小（真正的最小需要穷举请求排列，不可行），但通常性能优于FCFS —— 这是判断题的经典陷阱。

缺点是可能引发饥饿：若磁头位于18号磁道附近且附近持续有新请求到达（如20、16、21……不断插入），SSTF每次都优先服务这些"更近"的请求，磁头长期在18号附近来回，位于184号磁道的请求将永远排不上队。饥饿的本质是SSTF只贪图"局部最近"而无视"全局公平"，远处请求的等待时间可能无限期增长；而SCAN/C-SCAN类算法因方向约束保证每轮扫描必遍历全部请求，故不饥饿。

经典例题②之SSTF：从磁道100出发，逐个选择最近者 100→90（10）→58（32）→55（3）→39（16）→38（1）→18（20）→150（132）→160（10）→184（24）。总移动距离 = 10+32+3+16+1+20+132+10+24 = 248个磁道，平均寻道长度 = 248/9 ≈ 27.5，对比FCFS的498/55.3可见SSTF明显更优。易错点：从55到39后应先选距离更近的38（距离1）再选18（距离20），很多考生漏掉38导致答案与标准不同。

图5.23 SSTF——每次选最近请求，可能饥饿

六、SCAN（电梯）算法与LOOK算法（必考手算）

（3）扫描（SCAN）算法，又称电梯调度算法：为避免SSTF因磁头局部来回移动而产生饥饿，SCAN规定磁头仅在到达最外侧磁道后才转向内侧移动，到达最内侧磁道后才转向外侧移动，即在SSTF基础上引入磁头移动方向约束 —— 行为类似电梯（先沿一个方向逐层服务，到顶层再反向），磁头在单向移动途中顺路处理方向内的请求。优点：寻道性能较好、可避免饥饿现象（每个方向的请求最迟一个来回内必被服务）；缺点：对最近扫描过的区域不公平，远离磁头当前所在端一侧的请求响应较慢，在访问局部性方面不如FCFS与SSTF。做题时题目必须给出磁头当前移动方向，否则结果不确定。

经典例题③之SCAN（须到达端点）：磁头位于100号磁道，向磁道号增大的方向移动，磁道范围0~200（教材图例取最外端200）。先服务方向上（≥100）的请求150、160、184，到达端点200后反向，再从大到小服务90、58、55、39、38、18。访问序列为 100, 150, 160, 184, 200, 90, 58, 55, 39, 38, 18。逐步累加：|100-150|=50，|150-160|=10，|160-184|=24，|184-200|=16，|200-90|=110，|90-58|=32，|58-55|=3，|55-39|=16，|39-38|=1，|38-18|=20。总移动距离 = 50+10+24+16+110+32+3+16+1+20 = 282个磁道，平均寻道长度 = 282/9 ≈ 31.33。

图5.24 SCAN（电梯）——沿一个方向扫到底才回头

（4）LOOK算法（SCAN的改进型）：SCAN算法总是严格从磁盘一端移动到另一端，而实际上当某一方向已经没有待处理请求时，继续移动到底端是多余的。LOOK算法在朝某一方向移动前先"查看（look）"该方向是否存在请求：磁头只需移动到当前方向上最远的请求位置即可返回，无须抵达物理端点。实际系统中所称的SCAN算法通常即指LOOK调度，题目若不加说明，习惯按LOOK式处理（是否到达端点在题干中会特别说明）。

经典例题③之LOOK：仍为磁头100向上移动、请求队列同上。上升方向最远请求为184，故磁头到184即折返，不走到200。访问序列 100→150→160→184→90→58→55→39→38→18。逐步累加：|100-150|=50，|150-160|=10，|160-184|=24，|184-90|=94，|90-58|=32，|58-55|=3，|55-39|=16，|39-38|=1，|38-18|=20。总移动距离 = 50+10+24+94+32+3+16+1+20 = 250个磁道，平均寻道长度 = 250/9 ≈ 27.8。

图5.26 LOOK——SCAN 但不到端点即回头

对比可知：LOOK比SCAN省掉了"184→200→90"中"184→200"与"200→90"多出的部分（282-250=32），即省去了无请求的空跑。

SCAN类算法的方向敏感性：SCAN、C-SCAN、LOOK、C-LOOK 的结果强烈依赖磁头当前移动方向，题干必须给出"向磁道号增大（减小）的方向移动"。判断"中途新到达的请求能否顺路服务"只看它是否落在当前移动方向内：磁头正向上移动时，磁道号大于当前位置的请求可顺路处理，小于当前位置的只能等折返或下一轮，反之亦然 —— 与电梯行为完全一致（电梯上行时，处在下方楼层的新乘客必须等电梯下楼）。许多题目只把"方向"作为区分不同算法的唯一变量：磁头在67号磁道，请求为35、77、55、121，若希望"下一次"就到达55号磁道，只能采用电梯调度（SCAN）向磁道号减小方向移动（67→55 直接顺路处理），而SSTF下一次是77（距离10<12）、FCFS下一次是35、C-SCAN向上时下一次是77。

七、C-SCAN、C-LOOK算法、五算法对比与综合真题（必考手算）

（5）循环扫描（C-SCAN）算法：SCAN算法单向扫描时，磁头反向后立即处理反向请求，导致靠近两端磁道的请求响应快、中间区域响应慢的不公平现象。C-SCAN规定磁头仅沿单一方向移动并提供服务，到达末端后快速返回起始端（不处理任何请求），再以循环方式重新开始单向扫描。返回过程是"非服务性的快速跳转"，因此消除了对两端磁道请求的不公平性，使响应时间更均匀；代价是总移动距离比SCAN大（因为包含一次从末端到起点的空跑）。

经典例题④之C-SCAN（磁道0~200，向上）：先服务上升方向150、160、184，到达端点200后快速返回0（不服务），再从0向上依次服务18、38、39、55、58、90。访问序列为 100, 150, 160, 184, 200, 0, 18, 38, 39, 55, 58, 90。逐步累加：|100-150|=50，|150-160|=10，|160-184|=24，|184-200|=16，|200-0|=200，|0-18|=18，|18-38|=20，|38-39|=1，|39-55|=16，|55-58|=3，|58-90|=32。总移动距离 = 50+10+24+16+200+18+20+1+16+3+32 = 390个磁道，平均寻道长度 = 390/9 ≈ 43.33。

图5.25 C-SCAN——单方向扫描，回到端点直达另一端

（6）C-LOOK算法（C-SCAN的改进型）：与C-SCAN的LOOK化版本 —— 磁头只需移动到当前方向上最远请求处即返回，返回时也不服务，直接跳到最小（起始端一侧）的请求继续单向服务，无须到达物理端点。

经典例题④之C-LOOK（向上）：上升方向最远请求为184，到达184后快速返回（不服务）跳到最小请求18，再继续向上服务。访问序列 100→150→160→184→18→38→39→55→58→90。逐步累加：|100-150|=50，|150-160|=10，|160-184|=24，|184-18|=166，|18-38|=20，|38-39|=1，|39-55|=16，|55-58|=3，|58-90|=32。总移动距离 = 50+10+24+166+20+1+16+3+32 = 322个磁道，平均寻道长度 = 322/9 ≈ 35.8。可见C-LOOK比C-SCAN少了"184→200→0→18"中的空跑（390-322=68）。

图5.27 C-LOOK——C-SCAN 但不到端点即折返

方向变式例题（检验掌握程度）：同一队列、磁头仍在100号，但改向磁道号减小方向移动（端点仍取0与200），四种算法的结果全部改变 —— SCAN 100→90→58→55→39→38→18→0→150→160→184，距离 = 10+32+3+16+1+20+18+150+10+24 = 284（31.6）；LOOK = 248（27.5，恰好与SSTF总距离相同但序列不同，说明两算法数值可能"撞车"，务必按各自规则独立计算）；C-SCAN = 350（38.9）；C-LOOK = 282（31.3）。同一队列同一磁头，只改变方向结果就全变，因此解题第一步永远是"明确方向"。

综合真题式例题（2015、2019式）：某磁盘1000个磁道（编号0~999），当前磁头在734号磁道且向磁道号增大的方向移动，请求依次为164, 845, 911, 165, 788, 432, 396, 700, 25。

SCAN（非LOOK）：734→788→845→911→999（到端点）→700→432→396→165→164→25，距离 = 54+57+66+88+299+268+36+231+1+139 = 1239个磁道，注意SCAN必须算到端点999，否则结果会差一个"999-911=88"。SSTF：734→700（34）→788（88）→845（57）→911（66）→432（479）→396（36）→165（231）→164（1）→25（139），总距离 = 1131个磁道。

（补充）NStepSCAN与FSCAN算法（防磁臂黏着）：SSTF、SCAN、C-SCAN在特定情况下会出现磁臂黏着 —— 一个或多个进程频繁请求某磁道，使磁头长期滞留该区域，其他进程难以获得服务。NStepSCAN把请求队列划分为若干长度为N的子队列，调度器按FCFS原则依次处理各子队列，子队列内部用SCAN扫描；处理某子队列期间新到达的请求放入其他子队列，不插入当前子队列。N较大时趋近SCAN，N=1时退化为FCFS。FSCAN是简化形式：把队列固定分成两个子队列 —— 当前服务队列（按SCAN处理）与新请求队列（下一轮处理），通过"冻结当前、延后新请求"避免磁臂黏着，实现简单、开销低。

八、减少旋转延迟与提高磁盘I/O速度的措施

1. 扇区交替编号（交替命名）：磁盘连续旋转，磁头读完一个扇区后需要一定处理时间才能读下一个扇区。若逻辑相邻块在物理上也相邻，处理完当前扇区时下一个目标扇区可能已旋转越过磁头，需等近一整圈才能再次到达，造成显著延迟。为此对单个盘面的扇区采用交替编号，使逻辑相邻的块在物理布局上保持适当间隔，保证处理完一个扇区后下一个目标扇区恰好或即将转到磁头下方。以8扇区盘面为例：物理位置依次为0,1,2,…,7（连续编号），若系统处理一个扇区需要"转过1个扇区"的时间，则读完扇区0后扇区1已错过、需再等近一圈；改用交替编号（如物理次序0,4,1,5,2,6,3,7）后，逻辑相邻扇区在物理上相隔若干扇区，处理完扇区0时扇区4恰好转至磁头下，实现"边转边读"。

2. 盘面错位命名：各盘面同步旋转，同一柱面内的块通常按盘面顺序连续存放（盘面0扇区0~7、盘面1扇区0~7……）。读完盘面0的7号扇区后系统需处理时间，期间盘面1的0号扇区可能已错过，故对不同盘面实施错位命名 —— 把各盘面同号扇区在圆周上错开一个相位角，使盘面0扇区7处理完后盘面1扇区0恰好到达，首次经过即可读取，显著减少旋转延迟。两者优化对象不同：交替编号优化同一磁道的扇区间延迟，错位命名优化不同盘面间的延迟；它们减少的都是旋转延迟，而不是寻道时间。

3. 提高磁盘I/O速度的方法（2012、2018年考点）：

  1. 采用磁盘高速缓存：内存中开辟区域暂存磁盘块
  2. 调整磁盘请求顺序：即各种磁盘调度算法
  3. 提前读：读当前磁盘块时把逻辑上紧随其后的一个或多个磁盘块一并预读入缓冲区，应对可能的连续访问
  4. 延迟写：修改缓冲区数据时不立即写回磁盘，只设延迟写标志，待缓冲区被替换时再真正写盘，从而合并多次写操作减少I/O次数
  5. 优化物理块分布：链接或索引方式组织的文件尽量把块安排在同一磁道或相邻磁道，把若干连续扇区组成簇以簇为单位分配，减小磁头平均移动距离
  6. 虚拟盘（RAM盘）：用内存空间仿真磁盘，访问速度快，适合放临时文件；它与磁盘高速缓存的区别在于：虚拟盘内容完全由用户程序控制，磁盘高速缓存内容由操作系统透明管理
  7. 采用磁盘阵列RAID：某些RAID级别支持交叉存取，大幅提高磁盘I/O速度（详见下一节）

对容易混淆的三组概念再次辨析。

  • 磁盘高速缓存 vs. 内存缓冲：磁盘高速缓存使用内存中的区域暂存磁盘块，减少真实磁盘I/O；缓冲区则是协调CPU与设备速度差的临时存区，前者缓存"内容副本"、后者缓冲"数据流"。
  • 提前读 vs. 顺序访问：提前读是操作系统主动预取逻辑上邻接的块，与文件是否物理连续无关，命中率取决于访问局部性。
  • 延迟写 vs. 写直达：延迟写故意推迟落盘以合并多次写、减少I/O次数，代价是断电时数据可能丢失；写直达则是修改立即写回，数据安全性高但I/O次数多。这些词在选择题中常作为选项出现，关键是抓住"减少I/O次数"与"数据安全"这一对矛盾。

★ 高频真题考点与陷阱

  • 磁盘调度算法：FCFS 按请求次序、公平、不磁臂黏着、可能随时改变方向（Q630、Q648 2018）；SSTF（最短寻道时间优先）可能饥饿（Q629），计算（Q636：248；Q649 2021：41）；SCAN（电梯）单向扫描到端再回头（Q643 2009、Q645 2015：325）；C-SCAN 循环扫描到端直接跳回另一端（Q650 2024：788）；C-LOOK 等（Q621：CLOCK 是页面置换算法）。
  • 提高文件访问速度：提前读/连续簇分配/延迟写/磁盘高速缓存（Q647 2018）；不能改善 I/O 性能 = 多分区（Q644 2015）。
