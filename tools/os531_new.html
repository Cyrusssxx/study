一、磁盘的物理结构与地址构成

磁盘由表面涂有磁性物质的盘片构成，通过磁头（导体线圈）读/写数据：工作时盘片高速旋转，磁头沿盘片径向移动以定位目标位置。盘面上的数据存放在一组同心圆中，每个同心圆称一条磁道（宽度与磁头相当，一个盘面通常上千条）；磁道再划分为数百个扇区，每扇区大小固定（如 1KB），是磁盘寻址的最小物理单位，相邻磁道与相邻扇区之间留有间隙避免读写干扰。三者构成地址层次：盘片→磁道→扇区，实际定位由"柱面号·盘面号·扇区号"共同完成。

区域记录（ZBR）技术：传统设计每条磁道扇区数相同，而外圈磁道周长更大、线密度更低，磁盘容量被最内圈磁道的密度卡死，外圈空间白白浪费。现代磁盘把盘面划成若干环带，同一环带内磁道扇区数相同，外层环带的扇区数多于内层。2019 年以"磁盘容量计算"命题，做题务必分清题干给的是"每磁道扇区数相同"还是"按区域划分"两种模型。

扇区与磁道另有三个易考细节：

  1. 控制器每次读写都精确到扇区，而操作系统通常以"块"为单位提出 I/O 请求，两者粒度不同。
  2. 同一盘面的磁道由外圈向内圈编号，最内圈磁道线密度最大，是决定容量的瓶颈位置。
  3. 容量有两种口径：非格式化容量（含扇区间隙与校验信息的原始容量）与格式化容量（剔除控制器开销后用户可用的容量），后者总小于前者，命题中"磁盘容量"一般指格式化容量。驱动器由磁头臂、驱动盘片旋转的转轴与数据输入/输出电路组成，磁头臂与转轴的配合直接决定寻道时间与旋转延迟。

柱面：多个盘片垂直堆叠成盘组，每个盘面对应一个磁头，所有磁头装在同一磁头臂上同步径向移动；所有盘片上半径相同的磁道构成一个柱面。由此可推得关键结论：同一柱面上各磁道半径完全相同，列内切换磁道只需激活对应盘面的磁头，无须移动磁头臂——这正是"同一文件的数据尽量放同一柱面"的原因。于是磁盘地址取"柱面号·盘面号·扇区号"结构：柱面号决定磁头移动量（寻道开销的主要来源），盘面号决定激活哪只磁头，扇区号决定等盘片转到哪个位置。

容量公式：磁盘总容量 = 柱面数 × 盘面数（磁头数） × 每磁道扇区数 × 扇区大小。例如 1024 柱面、16 盘面、每道 512 扇区、每扇区 512B，则 1024×16×512×512B = 4GB。扇区大小有 512B、1KB、4KB 等多种取值，先统一单位再相乘；柱面数（=磁道数）与盘面数（=磁头数）是容量题中最容易漏乘的两个因子。

读/写一个磁盘块分三步，这三步正是"寻道时间、旋转延迟、传输时间"三部分时间的物理来源：

  1. 按柱面号移动磁头臂，使磁头定位到目标柱面；
  2. 激活对应盘面的磁头；
  3. 等目标扇区随盘片转到磁头下方，完成读/写。

二、磁盘的类型与地址换算经典题

磁盘按磁头可否移动分两类：固定头磁盘（每条磁道配一个磁头，无须寻道）与活动头磁盘（磁头沿径向移动定位，存在寻道开销，绝大多数机械硬盘属此类）；按盘片可否拆卸分固定盘（密封在驱动器内）与可换盘。1973 年 IBM 推出的温彻斯特磁盘采用"活动磁头＋固定盘片"，是现代机械硬盘的雏形。

分类的意义在于定位存取时间来源：固定头磁盘没有寻道时间，只剩旋转延迟与传输时间；活动头磁盘必须额外付出寻道，这正是需要磁盘调度算法减少寻道的根本原因。用户访问文件时，操作系统先做权限检查，再把逻辑地址转换为物理地址（逻辑块号→柱面号/盘面号/扇区号），最终变成对磁盘的读/写请求；磁盘虽是共享设备，但每次读写只能由磁头串行完成——多个请求如何排队、按什么顺序服务，直接决定平均寻道距离，这就是调度算法要解决的全部问题（它不决定"读哪个扇区"，只决定"先服务谁"）。

经典题①（地址换算，连续存放的下一块）：磁盘有 256 柱面、4 磁头、每道 8 扇区，编号从 0 起。文件 A 一块存放在5 号柱面、1 号磁头、7 号扇区，下一块应放何处？
分析：连续存放要求寻道开销最小，即同柱面内换盘面，先换磁头、后换扇区。故下一块为 5 号柱面、磁头号加 1 变 2、扇区仍为 7。答案：5 号柱面、2 号磁头、7 号扇区。

经典题②（记录号计算，必会公式）：磁盘有 100 柱面、每柱面 8 个磁道、每道 8 扇区，文件 A 含 6400 个逻辑记录（大小同扇区）顺序存放，第 0 个记录在 (0,0,0)，问地址 (78 号柱面、6 号盘面、6 号扇区) 存的是第几个记录？
分析：连续存放先填满扇区、再换盘面、最后换柱面，故每柱面可放 8×8=64 个、每盘面 8 个。记录号 = 柱面号×64 + 盘面号×8 + 扇区号 = 78×64 + 6×8 + 6 = 4992+48+6 = 5046。答案：第 5046 个逻辑记录。注意记录号从 0 计数，不要误加 1——这是丢分点。

三、磁盘的存取时间：三部分构成与平均存取时间

一次磁盘读写的总时间由三部分组成，这是本章最核心的公式，2014 年等真题直接以此命题：平均存取时间 Ta = 寻道时间 Ts + 旋转延迟时间 Tr + 传输时间 Tt。直白地说，一次读写 = 移动磁头（Ts）+ 等扇区转过来（Tr）+ 真正读数据（Tt）；Ts 随目标磁道距离变化，Tr 只由转速决定，Tt 由数据量与每道字节数决定。

两处最容易丢分：① Tr = 1/(2r) 里的 r 是转/秒，题目给的 7200 转/分必须先除 60，不换算会差 60 倍；② 固定头磁盘每道一个磁头、根本不用寻道，此时 Ts = 0，别再往公式里套。

① 寻道时间 Ts：活动头磁盘读数据前把磁头移到目标磁道的时间，含磁头臂启动时间 s 与跨越 n 条磁道的移动时间：Ts = m×n + s，其中 m≈0.2ms（跨每条磁道），s≈2ms（启动）。寻道时间取决于磁头移动距离，是调度算法唯一能直接影响的部分；若题干直接给"平均寻道时间"，直接代入即可，不必再乘磁道数。

② 旋转延迟时间 Tr：目标扇区转到磁头下方的平均等待时间。扇区位置随机，平均等半圈：Tr = 1/(2r)，r 为每秒转数。两个速查值必须背熟：5400rpm → 一圈 60/5400≈11.1ms、平均 5.56ms；7200rpm → 一圈 60/7200≈8.33ms、平均 4.17ms。旋转延迟只与转速有关，与磁头当前位置无关，调度算法无法优化，只能靠扇区交替编号间接改善。

③ 传输时间 Tt：读写 b 字节所需时间。若每道存 N 字节：Tt = b/(r×N)（r 为每秒转数），等价于"转一圈时间 × b/每道字节数"。它与数据传输率是同一物理量的两种写法——数据传输率 = N×r，反推 Tt = b/数据传输率：例如 7200rpm、每道 5120B，则传输率 = 5120×(7200/60) = 614400B/s = 600KB/s，读一个 1024B 块 Tt = 1024/614400 ≈ 1.67ms。考试按已知量选公式：给每道字节数就除以它，给传输率就除以传输率。切勿把"传完整条磁道"的时间当作单块传输时间。传输时间与转速成反比，由盘片物理特性决定，软件几乎无法优化。

核心结论：三部分中寻道时间占主导且唯一受调度算法影响；旋转延迟与传输时间都与转速成反比，转速是最重要的硬件参数，OS 层无法优化。故磁盘调度算法的主要目标就是减少平均寻道时间——前两项是"找数据"的时间，第三项是"传数据"的时间。

经典例题①（2014 真题式）计算
已知：7200rpm，平均寻道 4ms，每道 1600 扇区，每扇区 512B，读 1 个扇区—
① 一圈时间60/7200 = 1/120s ≈ 8.33ms
② 平均旋转延迟8.33/2 ≈ 4.17ms
③ 传输时间8.33×(1/1600) ≈ 0.0052ms（读 1 扇区可忽略）
④ Ta4 + 4.17 + 0.0052 ≈ 8.18ms

上例的易错点：切勿把平均旋转延迟算成整圈时间；1600 只参与传输时间计算，不参与旋转延迟；若问"读一个扇区的平均耗时"，答案应在 8ms 量级，明显小于任何含整圈旋转的选项。

扩展一（套 Ts 公式）：m=0.2ms、s=2ms、跨 n=50 条磁道，则 Ts = 0.2×50+2 = 12ms。由此可体会调度收益——若把平均跨越磁道数从 100 降到 40，仅寻道一项就从 22ms 降到 10ms。做题时区分题干给的是"平均寻道时间"（直接作 Ts）还是"m、s、n"三参数（代入公式）。

扩展二（三部分齐全）：5400rpm、平均寻道 5ms、每道可存 1MB，读 256KB。一圈 60/5400≈11.1ms，平均旋转延迟 5.56ms；Tt = 11.1×(256KB/1MB) = 11.1×0.25 ≈ 2.78ms；Ta = 5+5.56+2.78 ≈ 13.3ms。可见读取量接近一条磁道时，传输时间已不可忽略，三项都必须计入。若恰好传输整条磁道（b=N），Tt 就等于一圈时间，此时 Ta = Ts + 1/(2r) + 1/r = Ts + 1.5/r。

小题（纯传输时间）：3000rpm、盘面 10 个扇区，读一个扇区 → 一圈 60/3000 = 20ms，读 1/10 圈即 2ms。小题（理想传输率）：7200rpm、每道 160 扇区、每扇区 512B → 每秒传输 7200×160×512/60 ≈ 9,830,400B/s ≈ 9600KB/s。

九、独立磁盘冗余阵列（RAID）（必考判断）

RAID（独立磁盘冗余阵列）把多块独立物理磁盘组合成一个逻辑磁盘，目标有二：提高 I/O 性能（条带化把数据分块并行写到多块盘，交叉存取、吞吐倍增）与提高可靠性（镜像、奇偶校验等冗余，部分盘损坏仍可恢复）。各等级在"性能、容量利用率、容错能力、成本"四者间权衡。

等级实现方式可用容量（N 块容量 C 的盘）容错能力特点
RAID0条带化，无冗余N×C无（任一盘故障全毁）性能最高，利用率 100%；适合临时文件、缓存
RAID1镜像（两盘互为副本）N/2×C每镜像对坏 1 块可并行读，可靠性高，利用率仅 50%，成本高
RAID4条带＋专用校验盘(N-1)×C坏 1 块P = 各数据块异或；校验盘成写瓶颈
RAID5条带＋分布式校验(N-1)×C坏 1 块消除 RAID4 的写瓶颈，最常用
RAID6条带＋双校验（P、Q）(N-2)×C坏 2 块校验开销大、写性能更低
RAID10先镜像后条带（1+0）N/2×C每镜像对各坏 1 块至少 4 块盘，兼顾性能与可靠性

记忆要点：0 不冗余、1 靠镜像、4 用专用校验盘、5 把校验分散、10 先镜像再条带。RAID4/5/6 分别至少需 3、3、4 块盘，RAID10 至少 4 块。RAID0 追求性能牺牲可靠、RAID1 追求可靠牺牲容量，二者正好相反。

RAID10 与 RAID01 的差别（易错）：RAID10 先两两镜像成镜像对、再把镜像对条带化，任一对坏一块不致命（另一块镜像仍在工作，只是该组性能下降）；RAID01 先把数据条带化、再把整条带镜像，某条带一块盘故障则该条带整体不可用。两者都能容忍多块盘故障，但RAID10 单点故障后果更轻、重建更快，生产环境普遍用 10 而非 01。

选型四问：要最大容量且零容错 → RAID0；要绝对可靠且数据量小 → RAID1；要"容量＋单盘容错＋均衡性能" → RAID5；要高速同时双盘冗余 → RAID10（或 RAID6）。容量与容错一律按"可用容量 = 总容量 − 冗余容量"记忆：冗余盘对 RAID1 是 N/2、对 RAID4/5 是 1×C、对 RAID6 是 2×C。

经典例题⑤（4 块 1TB 盘组阵列）可用容量可容忍坏盘
RAID04×1TB = 4TB0 块
RAID1（两两镜像）2TB每镜像对各 1 块（共 2 块）
RAID5(4-1)×1TB = 3TB1 块，换盘后可重构
RAID104/2×1TB = 2TB每镜像对各 1 块

判断型设问的答法：RAID5 中某数据盘突然故障，系统仍能继续正常读写、不丢数据（其余数据盘与校验盘异或恢复），性能暂时下降——典型"以少量空间换高可靠性"。若"数据块依次写在盘 0、盘 1、盘 2…，而校验只写在一块固定盘"，该布局是 RAID4；若校验块也随数据块轮流分布到各盘，则是 RAID5。

奇偶校验的恢复原理（理解容错的钥匙）：设数据块 D1、D2、D3，校验块 P = D1⊕D2⊕D3（按位异或）。任一数据盘（如 D2 所在盘）故障后，可由 D2 = D1⊕D3⊕P 还原——即异或"已知 n-1 个可推出第 n 个"的特性实现了单盘容错，这也是 RAID4/5 只能容 1 块、而 RAID6 必须用两种校验（P 与 Q 的伽罗瓦域运算）才能容 2 块的原因。

读写特性两个要点：读可并行（各盘同时读不同条带，聚合带宽近似 N 倍单盘）；写需"读-改-写"（先读旧数据与旧校验、算新校验再写回，开销高于普通写）。故 RAID5 的小规模随机写会受校验计算拖累，而顺序大块写反因条带并行而很快。理解这两点即可回答"RAID 为什么能提速""RAID 为什么有写开销"类设问。

★ 高频真题考点与陷阱

  • 磁盘存取时间三部分里寻道最大（为什么）：寻道时间（磁头移到目标磁道，机械移动、最慢）＞旋转延迟（等目标扇区转到磁头下）＞传输时间（传送数据）→ 影响最大的 = 寻道时间（Q623、Q627），所以磁盘调度算法都围绕减少寻道（Q620）。
  • 读写单位 = 块（磁盘以块为单位与主存交换，Q622）；计算真题：3000 转/分 10 扇区 → 旋转一周 20ms、一个扇区 2ms（Q634）；7200 转/分 160 扇区 → 传输率 9600KB/s（Q635）；磁道访问序列计算（Q631、Q632）。
