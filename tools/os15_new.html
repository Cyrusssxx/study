一、引导过程的概念

操作系统以程序形式存放在硬盘等外部存储器中，常驻内存的只有操作系统内核，其余部分按需调入（磁盘上保存着完整系统）。

操作系统引导是指计算机通过执行一系列引导程序，依次定位启动设备 → 确定可引导分区 → 加载其中的操作系统内核，最终把控制权交给内核的链式过程。

之所以必须「逐级接力」，是因为内核映像有数百 MB 至数 GB，而固件一次只能从固定扇区读入很少的代码，CPU 复位后又只能从硬件约定的固定地址取第一条指令——只能靠「小的拉大的」，每一级引导代码都极小、只负责找到并加载下一级。

引导涉及的概念包括 BIOS、POST、CMOS、MBR、PBR、启动管理器（GRUB / Bootmgr），必须分清各自的位置与职责。

二、引导的完整七步链式过程（核心考点）

步骤执行者关键动作位置 / 产物
① 复位取指CPU从 ROM 的固定地址取第一条指令，执行 BIOS主板 ROM 中的 BIOS
② 自检选设备BIOS通电自检（POST）检 CPU、内存、外设；按 CMOS 中的启动顺序，选第一个有效启动设备确定启动设备（硬盘 / U 盘）
③ 读 MBRBIOS把启动设备的首扇区装入内存硬盘 0 号扇区（MBR）
④ 找活动分区MBR 引导代码解析分区表、识别活动分区，把它的首扇区装入内存活动分区首扇区（PBR）
⑤ 装启动管理器PBR 代码加载启动管理器（Linux 的 GRUB / Windows 的 Bootmgr）；多系统时提供选择菜单活动分区内的文件
⑥ 装内核启动管理器把选定的内核映像装入内存并跳转执行；内核完全接管，重建中断处理机制、不再依赖 BIOS内存 RAM 的系统区
⑦ 内核初始化内核建内核页表、PCB 链表与就绪 / 阻塞队列、设备控制块与 I/O 缓冲区，创建中断向量表，启动首个用户态进程 init完整的用户操作环境

BIOS初始化基本硬件并建立中断向量表，为引导阶段的设备访问提供支持；存放操作系统自举程序的芯片是 ROM（不是 SRAM、DRAM、CMOS、Cache），这是常考细节。

口诀：开机读 BIOS、自检选设备、MBR 找分区、PBR 找管理器、管理器载内核、内核建环境。每一步的执行者都是上一级引导代码，交棒即退出，不再返回。

MBR 的典型结构：占据硬盘第 0 号扇区，由 446 字节引导代码 + 64 字节分区表（最多记录 4 个主分区）+ 2 字节结束标志 55AA 组成；它只负责找活动分区、调入 PBR，不加载操作系统内核——这是 MBR 与 PBR（操作系统引导扇区）职责的本质区别。

初始化口径辨析：引导初始化阶段需要创建的是中断向量表；而硬盘分区表在硬盘分区时创建、文件系统根目录与索引节点表在逻辑格式化（创建文件系统）时创建，都不属于引导初始化的创建对象。

三、关键概念辨析

概念位置/载体作用
BIOS固化在主板ROM芯片上包含系统设置、基本I/O程序、开机自检程序和系统启动自举程序；初始化硬件、建立中断向量表
POSTBIOS执行的过程通电自检，检测CPU、内存、外设是否正常
CMOS主板上的配置存储器（电池供电）保存启动顺序、系统时间等参数，供BIOS选择启动设备
MBR启动设备首扇区（硬盘0号扇区）含引导代码＋硬盘分区表；解析分区表、找活动分区
PBR活动分区的首扇区（引导扇区）加载启动管理器
启动管理器活动分区内的文件GRUB（Linux）/Bootmgr（Windows），提供多系统/多内核选择界面，加载内核映像

引导程序分为两种：一种是位于 ROM 中的自举程序（BIOS 的组成部分），用于启动具体的设备；另一种是位于装有操作系统的硬盘的活动分区引导扇区中的引导程序（即启动管理器），用于引导操作系统——注意，操作系统的引导程序位于磁盘活动分区的引导扇区中，而非位于 BIOS 或 ROM（BIOS 只是自举启动的源头）。

整个链式过程的控制权转移顺序为：BIOS → MBR → PBR → 启动管理器（GRUB/Bootmgr） → 操作系统内核 → 内核初始化 → 首个用户态进程 init。

四、引导中的关键机制与补充要点

（1）硬件起头、软件接力：定位启动设备、读取 MBR 这些原始读取动作，由 BIOS 借助硬件中断向量表完成；从 MBR 开始，后续加载都由上一级引导代码（软件）完成。这也解释了为什么内核接管后要重建中断处理机制、不再依赖 BIOS。

（2）双系统 / 多系统引导：PBR 加载的启动管理器（GRUB 或 Bootmgr）提供操作系统选择菜单，按用户选择加载相应内核——开机后出现的系统选择界面正是它提供的。最终由哪个启动管理器主导，取决于 PBR 加载的是哪一个，通常由最后安装的系统或引导配置决定。

（3）BIOS 与 UEFI 的演进：传统引导基于 BIOS（固化在 ROM、支持实模式、通过中断向量表提供服务）；现代计算机多用 UEFI 替代——UEFI 同样作为固件位于 ROM 中，但支持保护模式、可直接从 FAT 分区读取引导加载程序，启动更快、支持的磁盘更大（传统 MBR 分区表最大约 2TB）。不论哪种，最终都要把内核装入内存并移交控制权，链式本质不变。

（4）ROM 里放的到底是什么：ROM 中只有引导自举代码，不是操作系统本身；操作系统代码始终存放在硬盘等外存中。自举程序不能放 RAM，因为 RAM 断电即丢，ROM 只读不丢，天然适合存放引导固件。

（5）运行位置：引导完成、内核接管后，操作系统内核及正在运行的程序均位于内存（RAM）；外存（硬盘）只用于长期保存。CPU 只能直接从内存取指执行，且内存存取速度远快于外存——开机引导的本质，就是把外存中的内核代码搬运到内存并开始执行。

五、两条主线与三句话总结

两条隐含主线：一是控制权的逐级移交（谁交给谁、交出后不再返回），二是加载对象从小到大的递进（BIOS 几十 KB → 内核数百 MB）。抓住这两条，题目换成「谁是主动方、谁被加载」的任何说法都能判断。

接力赛类比：BIOS 是起跑者，把接力棒（控制权）交给 MBR，MBR 交给 PBR，PBR 交给启动管理器，启动管理器交给内核，内核对准终点（init）。跑完自己那棒，前面的接力员就退出舞台。

引导过程与中断、设备驱动的串联：引导早期访问设备依赖 BIOS 建立的中断向量表，通过软中断读写磁盘；内核接管后重建中断向量表、加载真正的中断服务程序与设备驱动，此后一切 I/O 都走操作系统管理的正规通道——这就是「内核接管后不再依赖 BIOS」的含义。

复习记住三句话：第一，源头在ROM；第二，接力按 MBR → PBR → 启动管理器 → 内核的顺序逐级传递；第三，内核接管后重建中断与设备机制并启动 init。

六、经典例题

例1【2013统考真题】计算机开机后，操作系统最终被加载到（ ）。

A.BIOS B.ROM C.EPROM D.RAM。

推理：BIOS/ROM/EPROM中存放的是固化的引导程序，不可修改、速度慢；操作系统程序在开机引导过程中被从磁盘读取并加载到内存（RAM）的系统区中运行，RAM可读可写、速度快。故选D。

例2【2022统考真题】下列选项中，需要在操作系统进行初始化过程中创建的是（ ）。

A.中断向量表 B.文件系统的根目录 C.硬盘分区表 D.文件系统的索引节点表。

推理：操作系统引导的第七步中，内核初始化各子系统并建立中断处理机制——中断向量表是操作系统初始化时在内存中创建的（A对）；硬盘分区表在硬盘分区时创建、文件系统根目录与索引节点表在逻辑格式化（创建文件系统）时创建，均不属于操作系统引导初始化过程创建的对象。故选A。

例3在操作系统引导过程中，下列关于各阶段核心功能的描述，正确的是（ ）。

A.BIOS直接加载并执行操作系统内核 B.MBR解析硬盘分区表，并加载活动分区的引导扇区 C.启动管理器由BIOS直接从磁盘读取并执行 D.内核初始化阶段只需加载设备驱动程序。

推理：BIOS自检后仅加载主引导记录MBR并执行，不直接加载内核（A错）；MBR位于硬盘首扇区，通过解析分区表定位活动分区，并加载其分区引导记录PBR（B对）；启动管理器由PBR加载而非BIOS直接加载（C错）；内核初始化阶段除加载设备驱动外，还需初始化进程控制块、调度队列和空闲进程等调度相关数据结构（D错）。故选B。

例4检查分区表是否正确，确定哪个分区为活动分区，并在程序结束时将该分区的启动程序（操作系统引导扇区）调入内存加以执行，这是（ ）的任务。

A.MBR B.引导程序 C.操作系统 D.BIOS。

推理：BIOS将控制权交给排在首位的启动设备后，CPU将该设备主引导扇区的内容（MBR）加载到内存中，然后由MBR检查分区表、查找活动分区，并把该分区的引导程序调入内存执行。故选A。

例5【2021统考真题】在计算机开机引导过程中，下列说法错误的是（ ）。

A.引导程序先做硬件自检（POST）并识别已连接的外设 B.BIOS从ROM中读取并执行 C.引导程序将硬盘中存储的操作系统全部加载到内存中 D.装有双系统时，引导程序会与用户交互选择加载哪个系统。

推理：引导程序先做关键部位自检并识别外设（A对）；BIOS固化在ROM中、开机后自动执行（B对）；常驻内存的只是操作系统内核，操作系统其他部分仅在需要时才调入，把整个操作系统全部加载到内存的说法错误（C错）；装有双系统时引导程序（启动管理器）会与用户交互选择加载哪个系统（D对）。故选C。

例6下列有关操作系统引导的叙述中，正确的是（ ）。

A.MBR中的引导代码负责加载操作系统内核 B.PBR中的代码负责解析分区表并定位活动分区 C.内核接管系统控制权后仍依赖BIOS提供中断服务 D.内核初始化各子系统后启动首个用户态进程。

推理：MBR引导代码只负责解析分区表、定位活动分区并加载PBR，不直接加载内核（A错）；解析分区表、找活动分区是MBR的任务而非PBR，PBR负责加载启动管理器（B错）；内核接管后重建中断处理机制、不再依赖BIOS服务（C错）；内核初始化各子系统后启动首个用户态进程init，逐步构建用户操作环境（D对）。故选D。

例7下列关于引导过程与初始化过程关系的叙述中，错误的是（ ）。

A.引导过程在操作系统内核接管系统前完成 B.内核初始化是引导过程的最终阶段 C.引导程序执行时操作系统尚未运行 D.初始化完成后系统进入多道并发运行环境。

推理：引导过程到内核接管并完成初始化为止，内核接管后引导即告完成，初始化由内核自身完成（A对）；内核初始化属于引导过程的最后阶段（B对）；引导程序（BIOS、MBR、PBR、启动管理器）执行时操作系统内核尚未加载运行（C对）；初始化完成后系统进入正常的多道并发运行环境（D对）——本题中四句均正确，但需要注意「初始化由内核完成、引导由引导程序接力完成」的分界，命题常在此处设套。

七、易错点与命题陷阱

  • BIOS固化在ROM中、开机自动执行；而操作系统最终加载到RAM中运行；存放自举程序的芯片是ROM（不是CMOS、SRAM、DRAM、Cache）。
  • 引导链顺序不能颠倒：BIOS → MBR → PBR（引导块）→ 启动管理器 → 内核；MBR 在0 号扇区且含分区表，引导块在每个分区开头。
  • MBR 不加载内核，只找活动分区并把 PBR 调入内存（2021 例4/例6 反复考）。
  • 内核接管后不再依赖 BIOS；但引导早期访问磁盘靠的正是 BIOS 建的中断向量表。

八、考点提示

操作系统引导是考纲新增考点，2021、2022连续两年考查引导过程相关细节（引导中各阶段的职责划分、初始化过程中创建的数据结构），2013考「操作系统最终加载到哪里」，属于「记准位置 + 分清职责」的送分题，四个选择题选项往往就是四个阶段张冠李戴。

  • 操作系统引导（booting）的定义：把操作系统内核从外存装入内存并启动运行的过程。由于CPU 复位后只能从固定地址取指，必须由固化的引导程序逐级接力完成。
  • 引导的典型流程（顺序记忆）：① CPU 复位，从 BIOS 的入口地址开始执行；② BIOS 进行加电自检（POST）、初始化硬件；③ BIOS 读取磁盘 0 号扇区的主引导记录 MBR（含引导代码 + 分区表）；④ MBR 中的引导程序扫描分区表、找到活动分区；⑤ 读取该分区的第一个扇区——分区引导扇区（引导块 / PBR）；⑥ 由引导块把操作系统内核装入内存，并把控制权交给内核，操作系统启动完成。
  • 关键理解：引导是逐级接力的过程——BIOS → MBR → 活动分区的引导块 → 操作系统内核，每一级只负责把下一级装入内存并移交控制权。
  • 与计组的联系：MBR 位于磁盘的 0 号扇区，每个分区都以引导块开头（即使当前未安装可启动的操作系统也保留该区域）；在 Windows 中该区域称为分区引导扇区。
  • 易错：引导顺序不能颠倒——BIOS → MBR → 引导块 → 内核。
  • 易错：MBR 在0 号扇区且含分区表；引导块在每个分区的开头。
