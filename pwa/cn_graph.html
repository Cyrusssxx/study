③ 分层思想的考点 （封装 / 解封装 / 协议三要素）

  • 协议三要素：语法（格式）、语义（含义）、同步（时序）。
  • 封装：数据自上而下逐层加首部（链路层还加尾部 FCS），是「加头不加尾」的规律中唯一的例外——只有以太网帧有尾部。
  • 解封装：接收端自下而上逐层剥首部，交给对应上层。
  • 必考首部长度速记：TCP 20B / IP 20B / MAC 14B + FCS 4B / 前导码 8B（不计入帧长）。四者串联见文末「跨层串联」。
  • SDU 与 PCI：上层数据是下层的 SDU，加上下层的 PCI（协议控制信息）构成下层的 PDU。即 n 层 PDU = n 层首部 + n+1 层 PDU。

① 两种体系结构 C/S 与 P2P

维度客户/服务器 C/S对等 P2P
角色客户是服务请求方，服务器是提供方，角色固定每个结点既是客户又是服务器，角色可互换
服务器要求一直运行、固定 IP 与熟知端口、需大量服务器支撑无（或弱）中心服务器，可扩展性强
典型应用Web、FTP、SMTP、DNSBitTorrent、P2P 文件共享
  • 理论P2P 的最大优势是可扩展性：用户越多，总服务能力反而越大（C/S 是用户越多越慢）。

③ WWW 与 HTTP （连接方式与 RTT 计算是重中之重）

连接方式建 TCP 次数取 1 个对象的耗时共取 N 个对象
非持久（HTTP/1.0）每个对象 1 次2 RTT（1 建连 + 1 请求响应）≈ 2N RTT
持久非流水线（1.1 默认）共 1 次1 RTT（首对象 2 RTT）≈ (N+1) RTT
持久流水线共 1 次≈ 1 RTT（连续发请求）≈ 2 RTT 即完成
RTT 计算题套路：「1 RTT 建立 TCP 连接」+「1 RTT 请求并收到响应」= 2 RTT/对象（非持久）。三次握手恰好是 1.5 RTT 还是 1 RTT？考研题默认建立连接算 1 个 RTT（第 3 次握手的 ACK 与请求可合并/忽略），并通常忽略传输时延与处理时延——务必先读题干的"忽略"条件。
  • HTTP 报文：请求报文（请求行 + 首部行 + 空行 + 实体）／响应报文（状态行 + 首部行 + 空行 + 实体）。无状态协议——靠 Cookie 维持状态。
  • 常用方法：GET（取，参数在 URL）、POST（提交，参数在实体）、HEAD（只要响应头）、PUT、DELETE。
  • 必考状态码：200 成功 ｜ 301 永久移动 ｜ 302 临时移动 ｜ 304 未修改（命中缓存）｜ 400 请求错误 ｜ 403 禁止 ｜ 404 未找到 ｜ 500 服务器内部错误 ｜ 503 服务不可用。
  • Cookie：服务器在响应中加 Set-Cookie，客户机保存后每次请求带 Cookie 首部。Cookie 存在客户端，用于会话识别、个性化。
  • Web 缓存 / 代理服务器：以命中缓存的副本直接响应，减少时延与出口带宽；靠 Cache-Control / 条件 GET（If-Modified-Since → 304）保证新鲜度。
  • 区分HTTPS = HTTP + TLS，端口 443；HTTP 端口 80 明文传输。
  • URL 结构：协议://主机名:端口/路径?查询#片段。HTTP 默认端口 80 可省略。

  • SMTP 局限：只能传送 7 位 ASCII 文本，不能直接传图像/中文。

  • 基于万维网的电子邮件（如 Gmail）：浏览器↔服务器之间用 HTTP，服务器之间仍用 SMTP。

① 端口与复用分用 （传输层的寻址方式）

  • 端口范围：0~1023 熟知端口（服务器用）｜1024~49151 登记端口｜49152~65535 客户端临时端口。端口号共 16 位。
  • 复用：多个应用进程共用同一个传输层协议向外发送；分用：接收端按端口号把数据交付给正确的进程。
  • 必考套接字（socket）= IP 地址 : 端口号，唯一标识网络中的一个进程。TCP 连接由 {源IP, 源端口, 目的IP, 目的端口} 四元组唯一确定。

UDP 首部固定 8B；「长度」字段的最小值为 8（只有首部、无数据）。
  • 四大特点：无连接、尽最大努力交付（不可靠）、面向报文（不合并不拆分，一次交付一个完整报文）、无拥塞控制。
  • 必考UDP 校验和要加 12B 伪首部（源 IP 4B + 目的 IP 4B + 全 0 1B + 协议号 1B + UDP 长度 2B），伪首部只参与校验和计算、不实际传输。
  • 适用场景：实时音视频、DNS、DHCP、TFTP、SNMP —— 宁可丢包也不要大延迟。

首部最小 20B、最大 60B；「数据偏移」以 4B 为单位，故该字段最大值 15 → 15×4 = 60B。
  • 标志位 6 个：URG 紧急指针有效、ACK 确认号有效、PSH 尽快交付、RST 复位连接、SYN 同步序号、FIN 释放连接。
  • 易错序号与确认号都按「字节」编号，不是按报文段。TCP 是面向字节流的协议。确认号 = 期望收到的下一个字节的序号。
  • 必考SYN 与 FIN 各消耗一个序号（即使不携带数据），而普通 ACK 报文段不携带数据时不消耗序号。

  • 必考为什么四次？TCP 是全双工。服务器收到 FIN 后只表示"对方没数据要发了"，但自己可能还有数据要发，所以 ACK 与 FIN 必须分开发送（半关闭状态）。
  • 必考为什么等 2MSL？① 保证最后一个 ACK 能到达服务器（若丢失，服务器会重传 FIN，客户端还能响应）；② 让本连接产生的所有旧报文段从网络中消失，避免干扰后续新连接。
  • 保活计时器：服务器每收到一次客户数据就重置，若 2 小时无数据则发探测报文，连续 10 个无响应即关闭连接。

⑥ 可靠传输与流量控制 （滑动窗口 · 确认 · 重传 · rwnd）

  • 可靠传输四要素：序号 + 确认 + 重传 + 滑动窗口。TCP 采用累积确认（ack=n 表示 n 之前的全部已收到）。
  • 超时重传：用加权平均往返时间估计 RTT，超时时间 RTO 略大于估计值（考虑偏差）。超时时间过小 → 无谓重传；过大 → 迟钝。
  • 必考快速重传：收到 3 个重复确认（dup ACK）时立即重传丢失的报文段，不等超时——这是快恢复的前提。
  • 流量控制（接收方主导）：接收方通过首部「窗口」字段通告 rwnd，发送方据此调整发送速率。发送窗口 = min(接收窗口 rwnd, 拥塞窗口 cwnd)。
  • 易混零窗口 + 持续计时器：接收窗口为 0 时发送方停发，但启动持续计时器，超时后发零窗口探测报文，避免双方互相等待形成死锁。
  • 糊涂窗口综合症：发送方用 Nagle 算法（攒够一个 MSS 或收到 ACK 才发）；接收方等窗口够大（如半个缓存）或超时再通告。

⑦ 拥塞控制 （慢开始 · 拥塞避免 · 快重传 · 快恢复 —— 反复考的图）

  • TCP 的四种计时器：重传计时器、坚持（持续）计时器、保活计时器、时间等待计时器（2MSL）。

③ 子网划分与 CIDR （计算题必出）

例题：主机 192.168.1.100/26，求网络地址、广播地址、可用主机范围。
① 块大小：32 − 26 = 6 位主机号 → 每块 26 = 64 个地址。
② 网络地址：100 ÷ 64 = 1 余 36 → 落在第 1 段（从 64 开始）→ 192.168.1.64。
③ 广播地址：192.168.1.127（该段最后一个）。
④ 可用范围：192.168.1.65 ~ 192.168.1.126，共 62 台。
  • 子网掩码：网络号位全 1、主机号位全 0。掩码 AND IP = 网络地址；掩码取反 OR 网络地址 = 广播地址。
  • 必考CIDR 记法：a.b.c.d/n，n 为前缀长度（网络前缀位数）。CIDR 把「网络号 + 子网号」合并为网络前缀，不再区分 A/B/C。
  • 必考路由聚合（构成超网）：把多条前缀相同的路由合并为一条，如 192.168.0.0/24 与 192.168.1.0/24 可聚合为 192.168.0.0/23（能聚合的前提是前缀相同、地址连续）。
  • 最长前缀匹配：转发时若有多条路由匹配，选前缀最长（最具体）的那条。

⑤ ICMP 网际控制报文协议 （ping 与 traceroute 的原理）

类型报文用途
差错报告终点不可达路由/端口不可达（类型 3）
时间超过TTL 归零（类型 11）——traceroute 靠它
参数问题首部字段有误
改变路由（重定向）告知更优的下一跳（类型 5）
询问回送请求 / 回答ping 用它探测连通性与往返时延
时间戳请求 / 回答测量时延、时钟同步
  • 必考traceroute 原理：依次发送 TTL = 1, 2, 3… 的报文，每经过一台路由器 TTL 归零 → 该路由器回送 ICMP 时间超过报文，从而逐跳获得路径与 RTT。
  • ICMP 不报告差错的情况：对 ICMP 差错报文本身、对分片后的非首片、对多播/广播地址。
  • ICMP 封装在 IP 数据报中（协议号 1），属于网络层协议，不是传输层。

  • 经典坏消息传得慢（RIP）：网络故障后，错误路由会被相邻节点反复"纠正"式传播，导致慢收敛（计数到无穷）。对策：限定最大跳数 16、水平分割、毒性逆转。
  • 自治系统 AS：由同一管理机构管辖的网络集合。AS 内部用 IGP（RIP/OSPF），AS 之间用 EGP（BGP）。
  • 必考RIP 一条路由的"距离"是跳数，与链路带宽无关——所以 RIP 会选「跳数少但很慢」的路径，这是它的固有缺陷。
  • 路由器结构：输入端口 → 交换结构 → 输出端口，外加路由处理器。路由表项 = {目的网络, 下一跳, 接口}。

⑦ NAT 与 IPv6 （地址枯竭的两条出路）

  • NAT：在私有网与公网交界处做地址转换，把内网私有 IP 换成公网 IP。NAPT（端口复用）使多台内网主机共用一个公网 IP：维护 {内网IP:端口} ↔ {公网IP:端口} 的映射表。
  • 代价NAT 破坏了端到端透明性，使外网无法主动发起连接（需端口映射/打洞），也影响 IPsec 等协议。
  • IPv6 要点：地址 128 位（冒号十六进制，可用 :: 压缩连续 0，但一个地址中只能用一次）；首部固定 40B；取消了校验和、首部长度、标识/标志/片偏移字段。
  • 必考IPv6 的分片由源主机完成（路径 MTU 发现），中间路由器不分片——与 IPv4 的根本区别。
  • 过渡技术：双协议栈、隧道技术（把 IPv6 封装进 IPv4 数据报）。

⑧ IP 分片 （片偏移以 8B 为单位）

例题：一个总长 4000B 的 IP 数据报（首部 20B、数据 3980B），要经过 MTU = 1500 的网络，如何分片？
每片最大数据 = 1500 − 20 = 1480B（须为 8 的整数倍）
→ 片 1：数据 1480，片偏移 0，MF=1
→ 片 2：数据 1480，片偏移 1480/8 = 185，MF=1
→ 片 3：数据 1020，片偏移 2960/8 = 370，MF=0
三片总长分别 1500 / 1500 / 1040。
  • 必考分片只发生在网络层；同一数据报的所有分片标识字段相同，靠标识 + 片偏移 + MF 重组。
  • DF = 1 且必须分片时：丢弃该数据报并回送 ICMP 终点不可达（需要分片但 DF 置位）。

① 三大功能与两种信道 （点对点 vs 广播）

  • 三大功能：封装成帧（帧定界）、差错控制、流量控制与可靠传输。
  • 点对点信道：一对一（如 PPP 拨号），使用 PPP 协议。
  • 广播信道：一对多（如以太网局域网），必须使用介质访问控制协议协调共享信道。
  • 链路 vs 数据链路：链路是物理线路；数据链路 = 物理链路 + 实现通信协议的硬件和软件（网卡即典型）。

② 组帧的四种方法 （透明传输是核心）

方法原理优点 / 缺点
字符计数法帧首部用一个计数字段标明帧长简单；计数字段一出错就全乱，鲁棒性差
字节填充法用 ESC 转义标志字符（面向字节）PPP 采用；实现简单，但依赖 8 位字符
零比特填充法发送方遇连续 5 个 1 就插 1 个 0，接收方删HDLC 采用；透明性好、效率高（面向比特）
违规编码法用编码中不会出现的电平组合做定界无需填充；依赖特定编码（如曼彻斯特）
  • 必考零比特填充的判定：看到 111110 就是"5 个 1 + 填充 0"，接收方要删掉最后那个 0。标志字段是 01111110。
  • 透明传输：无论数据里出现什么比特/字节组合，都能原样正确传输（不把数据误判为定界符）。

③ 差错控制：CRC 与海明码 （检错 vs 纠错）

  • 必考CRC 计算步骤：① 数据后补 r 个 0（r = 生成多项式最高次幂）；② 与生成多项式做模 2 除法（异或，不借位）；③ 余数即 FCS，附在数据后发送；④ 接收方整体再做一次除法，余数为 0 则无错。
  • CRC 能检出多位错误，但只能检错、不能纠错；有 r 个校验位时能检出所有长度 ≤ r 的突发错误。
  • 必考海明码位数：要能纠正 1 位错，需满足 2k ≥ n + k + 1（n 为信息位，k 为校验位）。海明距离 d 与检错纠错能力：检 e 位错需 d ≥ e+1；纠 t 位错需 d ≥ 2t+1。
  • 奇偶校验：只能检出奇数个比特错，不能检出偶数个。

④ 流量控制与可靠传输 （停等 / GBN / SR 三张图必背）

停止等待后退 N 帧 GBN选择重传 SR
发送窗口 WT1≤ 2n − 1≤ 2n−1
接收窗口 WR11> 1（通常 = WT）
确认方式逐帧确认累积确认（ack=n 表示 n 之前全收到）逐帧确认 / 否认帧 NAK
重传策略超时重传 1 帧回退重传 n 帧（已发出的全重传）只重传出错的那一帧
乱序处理丢弃丢弃先缓存，等缺失帧到达后一并交付
n 的含义1 位序号n 为序号位数；窗口上限的差别是为了区分新旧帧
信道利用率公式（必背）
停止等待：U = TD / (TD + RTT + TA)
连续 ARQ（GBN/SR）：U = WT × TD / (TD + RTT + TA)，且 U ≤ 1
其中 TD = 帧发送时延，TA = 确认帧发送时延。
  • 易混为什么 GBN 的窗口上限是 2n − 1 而 SR 是 2n−1？GBN 接收窗口恒为 1，只需保证发送窗口内序号不重复即可多留 1 个；SR 接收窗口 > 1，若发送窗口 = 2n，则新旧帧序号会重合导致无法区分。
  • 最小序号位数：若窗口大小为 W，GBN 需 2n ≥ W + 1；SR 需 2n ≥ 2W。

⑤ 介质访问控制 （ALOHA · CSMA · CSMA/CD · CSMA/CA）

  • 信道划分（静态）：频分 FDM、时分 TDM、波分 WDM、码分 CDM（CDMA 靠正交码片序列区分用户）。
  • 纯 ALOHA：想发就发，冲突则随机等待重发，最大吞吐率 18.4%；时隙 ALOHA：只在时隙起点发，最大吞吐率 36.8%（翻倍）。
  • CSMA 三种坚持策略：1-坚持（空闲就发，冲突概率高）｜非坚持（空闲也不一定马上发，随机等一段）｜p-坚持（空闲时以概率 p 发送）。
CSMA/CD（有线以太网）：先听后发、边听边发、冲突停发、随机重发
① 争用期（冲突窗口） = 2τ（τ 为单程传播时延）—— 最迟要 2τ 才能确定没冲突。
② 最短帧长 = 2τ × 数据率。以太网 10Mb/s、2τ = 51.2μs → 512 bit = 64B。
③ 截断二进制指数退避：重传第 k 次时取 k = min(重传次数, 10)，从 [0, 2k−1] 随机取 r，退避 r × 2τ；连续 16 次失败即丢弃并报告。
④ 为什么最短帧长是考点：帧太短会导致发完了冲突才回来，发送方误以为发送成功。凡帧长 < 64B 的帧一律视为无效帧（碎片）丢弃。
  • 必考CSMA/CD 为什么不能用于无线？① 无线网卡收发不能同时（无法边听边发）；② 存在隐蔽站问题，冲突检测不到。故无线改用 CSMA/CA（冲突避免）。
  • CSMA/CA 机制：DIFS（普通帧等待）/ SIFS（ACK 等短帧优先，SIFS < DIFS）｜RTS/CTS 握手解决隐蔽站｜ACK 确认（无线不能靠冲突检测，只能靠确认）。

⑦ 交换机、网桥与 VLAN （自学习 + 冲突域/广播域）

  • 必考交换机自学习：收到帧时，把源 MAC 与入端口记入交换表；转发时查目的 MAC — 有表项则从对应端口单播转发，无表项则从其它所有端口洪泛。
  • 转发方式：直通式（收到目的地址就转发，快、不检错）｜存储转发式（收完整帧并校验再转发，可靠、时延大）。
  • 必考冲突域与广播域：
    · 集线器：所有端口在同一个冲突域、同一个广播域；
    · 交换机：每个端口是一个独立冲突域，整个交换机仍是一个广播域；
    · 路由器：隔离广播域（每个接口一个广播域）。
  • VLAN：把一个物理交换机逻辑划分为多个广播域，隔离广播、提高安全。IEEE 802.1Q 标签 4B（2B TPID + 2B TCI，含 12 位 VLAN ID，最多 4094 个）。
  • 生成树协议 STP：在冗余链路中逻辑地阻塞部分端口，消除环路、避免广播风暴。

① 码元与两大速率 （比特率 = 波特率 × log₂N）

  • 码元：承载数据的一段基本波形。N 种离散状态的一个码元可携带 log2N 个比特。
  • 必考波特率 RB（码元/秒，Baud）与 比特率 Rb（bit/s）的关系：Rb = RB × log2N。
  • 例：波特率 2000 Baud、每码元 4 种状态 → 比特率 = 2000 × 2 = 4000 bit/s。若每码元 8 种状态则 ×3。

② 两大定理 （算最大数据率，必出计算题）

定理适用条件公式含义
奈奎斯特准则 理想低通信道，无噪声 C = 2W · log2N 带宽 W 决定了码元速率上限（2W 波特），再乘每码元比特数
香农定理 有高斯噪声的信道 C = W · log2(1 + S/N) 噪声限定了可用的码元数，W 或信噪比越大，极限速率越大
两道典型题
① 带宽 3kHz、每个码元 4 种取值、无噪声：C = 2×3000×log24 = 12000 bit/s。
② 带宽 3kHz、信噪比 30dB：先换算 S/N = 1030/10 = 1000，再算 C = 3000×log2(1001) ≈ 3000×9.97 ≈ 30 kbit/s。
坑：题目给的是 dB，必须先换算成倍数 S/N 再代入！

③ 编码与调制 （数字↔数字 / 数字↔模拟 / 模拟→数字）

编码方式规则考点
NRZ 不归零高电平=1，低电平=0简单，无法自同步（长串同电平时收不到时钟）
曼彻斯特每个码元中间必有一次跳变（高→低=1，低→高=0）自带时钟同步；频带宽度是数据率的 2 倍（考点！）
差分曼彻斯特位中间总有跳变；位开始处有跳变=0，无跳变=1抗干扰能力更强
4B/5B4 位数据映射成 5 位码提高编码效率（100Mb/s 以太网用）
  • 数字数据 → 模拟信号（调制）：ASK 幅移键控 ｜ FSK 频移键控 ｜ PSK 相移键控 ｜ QAM 正交幅度调制（幅+相结合，每码元承载更多比特）。
  • 必考模拟数据 → 数字信号（PCM）三步：采样 → 量化 → 编码。采样必须满足采样定理 f ≥ 2fmax（否则失真/混叠）。
  • 电话系统的经典数据：语音最高 4kHz → 采样 8000 次/秒 → 每次量化编码 8 位 → 8000 × 8 = 64 kbit/s。

④ 信道复用 （五种复用 + CDMA 计算）

复用方式划分维度特点
FDM 频分频率各用户占不同频段，同时发送，需保护频带防串扰
TDM 时分时间各用户占固定时隙，时隙固定分配、空闲也浪费
STDM 统计时分时间（按需）按需分配时隙，效率高于 TDM，但需地址标识
WDM 波分波长（光纤）本质是光的频分复用，一根光纤跑多路
CDM 码分编码各用户用正交码片序列，同频同时发送互不干扰
  • 必考CDMA 计算套路：每个站的码片序列互相正交（规格化内积为 0）。站发 1 → 发自己的码片序列；发 0 → 发反码；不发 → 全 0。接收时用该站码片序列与收到的信号做规格化内积：得 +1 → 该站发了 1，−1 → 发了 0，0 → 没发。

⑤ 传输介质与物理层设备 （会看会选即可）

  • 导向介质：双绞线 UTP/STP（成本低、易受干扰）｜ 同轴电缆（抗干扰较好）｜ 光纤（带宽极大、抗电磁干扰、衰减小、保密性好，分单模（远距离、贵）与多模（近距离））。
  • 非导向介质：无线电波、微波（直线传播，需中继）、红外。
  • 必考中继器：对信号整形、放大、再生，仅延长传输距离，不隔离冲突域；集线器（Hub）是多端口中继器，所有端口共享带宽、同属一个冲突域。
  • 物理层不寻址：它只负责在介质上透明地传输比特流，不关心比特的含义，也不识别地址。

③ 设备、层次与冲突域/广播域 （一表定音）

设备工作层隔离冲突域隔离广播域关键词
中继器 / 集线器物理层否否放大再生信号，共享带宽

路由器网络层是是（每接口一个）查路由表，TTL 减 1

  • 常错「交换机隔离广播域」是错的——交换机默认不隔离广播域（除非划 VLAN）；只有路由器（或 VLAN）能隔离广播域。
  • 域的计算：n 台集线器互联仍只有 1 个冲突域；一台 24 口交换机 + 若干集线器，则冲突域 = 集线器上联的端口数，广播域仍为 1（若不划 VLAN）。

④ 双重（甚至三重）控制机制 （同一件事在不同层各做一遍）

功能数据链路层传输层
差错控制CRC 检错，坏帧丢弃（点到点）校验和 + 确认 + 重传（端到端）
流量控制滑动窗口（GBN / SR，相邻结点间）接收窗口 rwnd（两端进程间）
拥塞控制—慢开始 / 拥塞避免 / 快重传快恢复
可靠传输可选（PPP 就不做）TCP 必做，UDP 不做
  • 理解「链路层负责一跳，传输层负责全程」——链路层的可靠只保证一段线路，若中间路由器出问题仍可能丢包，所以端到端的可靠性必须由 TCP 兜底。
